\section{Evaluation goals}
\label{sec:evaluation-goals}

The object of this chapter is the automated pipeline as a whole: a B goal enters, an SMT script is produced, and a solver either discharges the goal or does not.
The pipeline's design rests on two decisions defended in the preceding chapters---representing sets by characteristic predicates and functions by function values rather than by a first-order membership axiomatization (\Cref{ch:beer}), and reconciling the resulting representations through type loosening (\Cref{ch:loosening}).
Both decisions were justified there on semantic and proof-theoretic grounds; whether they help an actual solver is an empirical question, addressed here through four assessments:

\begin{description}[font=\normalfont\emph]
  \item[Effectiveness:] of all goals in the corpus, how many does the pipeline discharge end to end, and what stops it on the rest?
  \item[Quality:] when both encoders produce a script and the solver reaches a verdict on both, which encoding serves the solver better?
  \item[Structure:] which classes of goals favor which encoding---and do the design choices of \Cref{ch:loosening,ch:beer} pay off where they were predicted to?
  \item[Cost:] what do the higher-order scripts cost in solver time and script size?
\end{description}

The comparison point is \emph{ppTrans}, the translator distributed with Atelier~B~\cite{lecomte2024proving} and the industrial reference for using SMT solvers to discharge B proof obligations~\cite{deharbe2014integrating}.
Its design is the opposite pole of \beer's: set-theoretic constructs are compiled away into first-order formulas over simple membership predicates, so no set, function, or relation survives as a first-class value.

The questions above concern the encoding \emph{design} at full scale, so the encoder under test is \textsc{Zero-Proof} \beer{} (\Cref{sec:beer-zero-proof}).
It applies the encoding rules of \Cref{ch:beer}, extended to a larger fragment of B---cardinality, finiteness, sequences, transitive closure, generalized sum and product---and is optimized for throughput: efficient data structures like hash-maps, arrays, linear state updates, and with the artifacts specifically added for the proof of correctness removed (like dependent in-domain test guarding each context lookup, the copy of the context taken at every binder, \etc).
It shares the design of the verified encoder, and its implementation lies outside the soundness theorem of \Cref{sec:beer-soundness}.

Scripts from both translators are then processed by cvc5~\cite{barbosa2022cvc5}, the reference implementation of higher-order SMT solving~\cite{barbosa2019hosmt}.
The choice is largely forced on one side---\beer{} emits \texttt{HO\_ALL} scripts that no other solver accepts---and neutral on the other: ppTrans's output is first-order, a fragment on which cvc5 is routinely competitive.

\begin{note}
The interactive route through \barrel{} is not evaluated here: a proof-assistant integration is exercised by users rather than by a corpus sweep, and \Cref{ch:barrel} discusses it qualitatively.
\end{note}
